# 科学站整体地编：v17 总图与实施门槛

状态：**v17 E1/E2 灰盒均未过三机位视觉门槛，正式场景仍为 v10B。** 本文记录站区空间问题、两案试验与后续实施门槛；不更改 MicroDuck 的 observation/action、60Hz 固定步或训练契约。尺寸使用 Bevy 世界坐标（米，`x` 向东、`z` 向南）；文中候选坐标不是已批准的施工位置。

## 要解决的问题

原场地的中央浅色广场主要为了扩大行走面积：主舱在北，圆形样本楼在西，维修舱在东南，两塔及工作设备分散。v10B 已给主舱增加可见且可碰撞的西翼，但从总览看，建筑仍没有组织成完整的站区。v11–v16 分别试过东侧雨棚、建筑粗移、四棚、操作台、矮服务边和东檐小翼；真实 GPU 画面显示它们遮塔、割裂地面或退化为散家具，均未晋升。

新总图保留中央 **11×9m 行动核心**、约 **3m 环路**、**2.8m 山路**、七条现有支路和三个安全点。空场是机器人活动面；要重排的是其外围的建筑门口、工作面与道路关系。北侧保持主舱入口作为南入口轴终点和双塔的完整轮廓；西侧把圆形样本楼、旧 `plant` 与室外取样设施组织成处理链；东侧使维修建筑、泊位和工具真正形成一个工程区。地面用连续、低对比的铺装与接缝说明通行，不再画断开的橙色岛或把原沙地抬高成假门槛。

## 两套东侧灰盒同时比较

| 方案 | 建筑关系 | 主要风险 |
|---|---|---|
| E1：旧舱保留 | 保留东南旧 `service` 舱，在其北侧规划一座有门口、工作面和实墙体量的维修间，围合原泊位设施。 | 新建筑可能遮挡双塔脚架；若只剩一座孤楼，仍不能解决整体布局。 |
| E2：旧舱迁移 | 把旧 `service` 舱与其源显示面、151 个凸碰撞体、5 个标签一起迁至旧工作台北侧；原址改为开放装卸前场。`(+8,0,-13)m` 仅供灰盒试位。 | 单独迁舱在总览投影会比旧址更小，必须连同建筑群和铺地一起审查；新址还需实测地质、地面支承、门外净空和塔脚遮挡。 |

两案共用西侧圆楼与 `plant` 的低处理廊，以及外围连续路网。廊道须与旧屋面、门和设备接口实际接合，不能把盒体贴在旧楼背后；山路净宽和安全点仍须保留。东侧的泊位工作台、货架、连接器、训练道具和表面图形是与旧 `service` 舱分离的资产；E2 不得把只搬旧舱说成整个泊位已经迁移。两案优先拍旧固定 `overview`、`arrival`、`berth` 三机位真实 GPU 图并并排比较；任何一案若形成前景大板、塔脚遮挡、孤楼或断路，就停止该案，不做正式碰撞迁移。

## 从灰盒到正式场景

只有三机位能清楚读出北指挥、西样本、东工程、开放中庭和南入口，才继续检查 `samples`、`hills`、`towers`，共六机位。可接触的新楼、廊和铺地必须由同一几何源生成显示三角与静态碰撞；旧舱若移动，必须精确变换共享材质网格中的对应顶点前缀、原 151 个凸体与标签，未移动的塔、地形、岩石、道具和旧设施逐项证明不变。不能用一只粗碰撞盒替代旧舱，也不能只改 `layout.zones` 锚点：现有 GLB 的站体顶点已经在世界坐标。

正式方案应升级布局 revision/identity，并同步独立 layout RON、manifest 内嵌布局、GLB 与布局 SHA、运行时身份校验和历史兼容测试。随后按六视角 GPU、结构/渲染测试、唯一物理世界零步导入、门口/地面接触及实际机器人通路的顺序验收。局部球体接触或静态 AABB 净空只能作预筛；旧场景录像和旧技能评价不能自动用于新场地。

## v17 实拍结论与下一阶段

E1、E2 各有三张旧固定机位的真实 GPU 灰盒图，均正常输出，**但均不进入正式资产**。两案共用的西处理廊在入口和泊位视角呈圆楼背后的深色横盒；E1 的北维修间在总览是独立小楼，在泊位遮住 02 塔脚；E2 搬后的旧舱在总览变远变小，在泊位以大散热栅背面朝向工作台，旧址又留下孤立的泊位标记。候选未获得六机位或物理资格。

下一轮不能只微调 E1/E2 的坐标或表面颜色。应先在俯视关系和三维视线中**同步重设计**西侧圆楼背面与 `plant`、东侧维修舱与泊位工具及其入口朝向、连接两塔的支路、山路入口和庭院外缘；明确每栋楼的正面、门口、工作面和可走连接，再建具有原场景细节尺度的体量。可增加新的展示机位判断整体设计，但旧六机位必须保留作遮挡与通路回归，不能靠换镜头掩盖问题。旧建筑若被删除或重组，显示面、原凸碰撞体、标签、fixture、表面图形和布局身份必须一起变更并重新验证。
