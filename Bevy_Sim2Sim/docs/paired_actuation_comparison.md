# 同力矩单步对照：关节映射成立，运动中求解仍有差异

更新日期：2026-09-28。冻结腿式和轮式完整本体，分别在原位零速、仅关节运动、仅根体运动、根体及关节同时运动的同一 `qpos/qvel` 下，对 14 路源序执行器施加相同非零力矩 `[0.12,-0.08,0.05,-0.11,0.16,-0.09,0.07,-0.13,0.04,0.15,-0.06,0.10,-0.14,0.03] N·m`，各做一次真实 `1/60 s` 积分。该向量 SHA256 为 `1a566de67c160ceb780cb28ea627bf5d3933dac828c684ce9498f5c7b69a77f5`。源 `.mjb` 的 14 个执行器经运行时核对均为 unit-gain、unit-gear、无 bias 的关节 motor，且此向量位于各自控制和力矩范围内；`mj_step` 实际 `qfrc_actuator` 与输入逐路相同。Rapier 侧通过现有 `actuator_body_torques` 生成成对刚体力矩，新增只读的 `Jᵀ` 用户力/力矩投影记录，以区分映射与动力学差异。没有运行策略、BAM、站体或 SourceCollisionWorld。

无力矩的对应运动状态，步末速度差不超过约 `2.6e-7 rad/s`。这组结果支持执行器关节顺序、符号和实际广义输入投影正确；它同时暴露了运动状态下**非零控制与动力学求解的耦合差异**。不能把它归因为 BAM，也不能据此认定 Rapier 目标 plant 等价。尤其外载残差小并不保证同控制下一步状态一致。后续需分辨速度相关惯性、积分和求解器处理，继续使用同输入的步末运动作为门禁。

另做一项**诊断性 oracle 注入力**，只为隔离关节限位差异：从原始 MuJoCo 超限单步读取 `head_roll` 的实际 `qfrc_constraint`（腿式 `−0.0351088073 N·m`、轮式 `−0.0351108102 N·m`）；在各自 scratch 编译定义中仅关闭这一关节的 Rapier 硬限位，把该已知源力作为同一步外力输入。与原 MuJoCo 零控制超限单步相比，腿式步末位置/速度差 `9.15e-9 rad` / `4.28e-7 rad/s`，轮式 `1.74e-8 rad` / `5.35e-7 rad/s`。这证明在此**零初速、单活跃限位的特定状态**，已知源约束力可通过当前力矩映射和积分重现终态；它没有独立计算限位力，不能作为生产软限位实现。两个 scratch 变体定义 SHA256 分别是 `5d927f0489d2e892a5d51cf168e0b954e100d3fbe314dbf8d4bd015c7fad9284` 和 `601d3aedc53dfd4ea9d0f157ef441f080c02687fd56a1b00b2aa77d783905ae9`。正式定义未更改。

本机逐项原始收据在 `.scratch/paired_force_v1/`：八组 `*_actuated_rapier.json` / `*_actuated_comparison.json`、两个 `*_limit_oracle_rapier.json`，以及汇总 `actuation_manifest.json`（SHA256 `6a1bf19e4f73fcf52678297a3462736199b81134a323cc233ed53940b4088d68`）。Rust 探针新增可选的 `QVEL QVEL_SHA TORQUES TORQUES_SHA` 参数；Python 比对脚本新增 `--torques TORQUES --torques-sha256 SHA`，两侧同时校验输入文件身份与 MuJoCo 实际 actuator 输出。所有报告仍标记 `bam_external_load_qualified=false`。限位参数、单行质量与下一步实验矩阵见 [限位法则调查](limit_law_investigation.md)。
