# MicroDuck MVP 与 Bevy Sim2Sim 实施计划

更新日期：2026-09-28。当前首阶段为 MicroDuck 腿式形态与原有 Walk 策略的完整 MVP。

## 成功条件与阶段

### 第一阶段：MicroDuck MVP

贯通 `Rapier 状态 → 观测 → 本地 ONNX → 关节目标 → 力矩 → Rapier 积分`。完成站立、前进、转向、停止、重置及固定输入回放；通过数值、关节、接触、时序和重复运行检查。显示保留原有机器人模型、比例、材质、描边和光照，并以对应机位核对。

### 第二阶段：完善 MicroDuck 与独立地图

承接其余有效 MicroDuck 技能、Sprint、轮式形态以及真实关节驱动的抓取与释放。迁移 `science_station` 和 `small_workshop` 两张独立地图，完成地图操作、相机及探索体验，验证完整场景的原有视觉风格，再进行对应场景的运行效率和开发效率比较。

### 后续阶段：逐步引入 SaiRobot

在已有链路通过后接入其现有模型、策略、物理频率和交互，并按各自契约回归。后续阶段启动时以当前仓库和实际运行核实具体资产及验收门槛。

每阶段交付可运行工程，记录功能覆盖、测试条件和遗留问题。

## 工程起点与模块

技术起点为 Rust 1.95、Bevy `=0.19.1`、`bevy_rapier3d =0.36.0`，使用发布绑定锁定的 Rapier。ONNX 采用 `ort =2.0.0-rc.13`，关闭默认特性，启用 `std`、`load-dynamic`、`api-28`，加载固定版本 ONNX Runtime 1.29。版本核查及组合风险见 [研究记录](research.md#依赖与版本选择)。首次创建工程后生成并提交 Cargo.lock，再执行带 `--locked` 的检查。

仅随实际功能创建以下模块：

| 模块 | 职责与依赖 |
|---|---|
| `robot_minigame` | 模型与控制契约、观测、动作解释、状态历史、ONNX；不依赖 Bevy/Rapier |
| `simulation_minigame` | Bevy/Rapier 组装、物理生命周期、输入、场景和画面；单向依赖机器人模块 |
| `dev_tools_minigame` | 按需实现回放验证、检查和测量；根包 optional，非默认 `dev_tools` feature |

根入口负责启动和装配。加载后的定义与配置不可变，运行状态另存。出现实际跨模块、业务无关接口时再按规范建立公共层。模型、契约、图形资产和 shader 落点遵循 [工程规范](../bevy_engineering_rules.md) 及用户允许的 ONNX/JSON 落点。

## 首阶段实现顺序

### 1. 准备可测基线与最小工具链

在 DGX 上核验架构、GPU/驱动、Vulkan、窗口条件和原生库。准备独立的 `.scratch/` Godot 对照运行环境，生成缺失资源，核对当前有效模型与物理定义，录制 MicroDuck 固定输入及对应机位。保留原工程和工作区状态。

创建最小 Bevy workspace，验证带渲染与无窗口启动。启动屏障必须等待所需资产和渲染管线就绪；缺失资产、坏模型、原生库错误和 shader 失败明确报错并以非零状态退出。发布时显式解析资产根，验证从其他工作目录启动。

### 2. 实现实际机器人刚体和关节

读取原始质量、主惯量、惯性位姿、关节轴、限位、初始姿态、碰撞体及执行器顺序。使用坐标变换 `(x,y,z) → (x,z,-y)`，刚体按惯性质心坐标系组装，视觉、碰撞及关节锚点转换到各自局部坐标。完整质量属性与 collider 质量贡献分开设置。

使用多体关节树，按实际自由度位置设置 armature，主动关节 `.0018`。保留有效脚底几何、摩擦组合、碰撞过滤和无休眠配置。具体原始参数与转换差异见 [物理契约](research.md#物理与观测契约)。

先通过单关节惯量/armature、正负力矩、限位、非零初态及完整关节树能量检查，再接入策略。若复现已定位的上游数值问题，移植最小兼容修复并重跑整组回归。

### 3. 实现观测、推理与力矩驱动

保持 61 维观测顺序、机体坐标还原、姿态差分、动作历史和动作计算中的 f32 舍入。gyro 先在世界坐标做差分和 5 ms EMA 再转机体局部，qd 的 wrapped 差分同样做 5 ms EMA。先对相同输入检查 Rust 观测与目标，再重跑 ONNX 冻结样本，最后记录实际物理观测轨迹。

推理采用 CPU、单线程、顺序执行和全图优化。初始化一次 Session 与固定缓冲区，验证模型 SHA、名称、类型和维度；输出复制到归属明确的动作缓冲区后再复用输入。推理错误或非有限值进入明确失败状态。

每步按当前有效控制参数计算：

```text
tau = clamp(kp * (target - q) - kv * qd, torque_min, torque_max)
      - damping * qd - frictionloss * tanh(qd / 0.05)
```

MicroDuck 起点为 `kp=.55`、`kv=0`、限幅约 `±.64052362 Nm`、阻尼 `.053`、摩擦损失 `.0048`。每步先清除受控刚体的上一轮用户力矩，汇总所有关节的父子反向力矩再施加，确保被动力只计算一次。

### 4. 固定步调度与生命周期

MicroDuck 固定步为 5 ms，策略每 4 步执行，首个策略调用发生在第 0 步积分前。Bevy 中控制系统置于 Rapier `SyncBackend` 之后、`StepSimulation` 之前，按以下顺序串联：

```text
同步物理实体与关节
→ 初始化新句柄、关节姿态及 armature
→ 读取 s[n] 并更新观测器
→ n % 4 == 0 时消费输入、更新控制指令、推理并保持目标
→ 按 s[n] 计算、汇总并施加力矩
→ Rapier 单步积分 dt=.005
→ Writeback
→ 记录已完成步并增加步号
```

输入事件在渲染阶段捕获，控制边界消费一次；冲突方向键沿用最后按下者优先的行为。显示插值只更新视觉子实体，策略始终读取物理状态。

重置冷重建机器人关节图及其交互约束，待后端同步删除和创建后初始化非零姿态，清空速度、用户力、动作历史、观测器和控制状态。暂停同时冻结仿真和 episode 时钟，回放全局时间与 episode 时间分开维护。

### 5. 运行、回放和视觉回归

对站立、前进、转向、停止分别执行 15 秒场景，重复三次，记录状态、动作、力矩和接触。先定位差异属于观测、动作、力矩还是积分，再修复相应层。

固定输入按物理步编号回放，保存种子、控制事件、模型哈希及物理配置。30/60/144 FPS 使用同一输入步序列；400 步必须为 400 次力矩更新、100 次推理。注入 500 ms 停顿，报告实际执行步数、欠账和被截断时间。

重建原有分段光照、局部排线、像素宽度描边、镜片材质与距离衰减。比较固定分辨率、投影、机位、姿态、光照和抗锯齿下的截图，录像检查运动中的轮廓和接触表现。

## 验收门槛与失败处理

| 检查 | 门槛及覆盖 |
|---|---|
| 契约 | 模型/spec 哈希、执行器顺序、维度和坐标全部匹配；同输入观测/动作计算采用原始 `1e-7` 数值检查 |
| ONNX | Rust 端冻结样本输出满足原有 `1e-5` 容差；实际物理观测另行回归 |
| Armature | 单关节 `.0018` 与已知惯量的加速度符合公式；保留刚体主惯量 |
| 关节树 | 无重力自由运动与限位测试有限、稳定；记录能量、角度和求解残差 |
| 接触 | 实际脚底落地、倾斜及滑移检查接触位置、冲量和穿透；按 `0.2 mm` 起始线性接触容差验证收敛 |
| 重置 | 初始角度误差不超过 `1e-3 rad`；速度、动作和观测历史清空；20 次接触重置无句柄增长 |
| 时序 | 400 步/100 推理计数严格通过；显示帧率和停顿不改变输入步序列 |
| 运动 | 固定输入重复实验有限、无异常退出；对照 Godot 的站立、路径、朝向和停止状态 |
| 视觉 | 对应机位逐项核对模型比例、色彩、排线、材质、描边和光照；记录差异与人工确认结果 |
| 生命周期 | 坏模型、缺资产、错误 shader、退出、暂停及重置都有明确行为和结果 |

物理起点使用米单位、单步积分、零预测距离、关闭接触缓存复用和保守求解设置。先从 32 次外部求解迭代开始做收敛实验，内部迭代保持绑定默认值；记录并冻结通过精度门槛的参数。Godot/Rapier 迭代次数不能直接视为相同精度。

单项失败提交最小复现到 `.scratch/`，保留原控制与精度基线，依据数值原因修复，再执行对应回归和完整闭环检查。重复通过一次构建或截图不能替代整组验收。

## 后续验证与效率测量

第二阶段对轮式形态、技能切换和真实抓取追加回归。被动轮保持无主动驱动；抓取使用关节、接触和场景刚体，加入辅助关节后的质量变化须重新验证移动。

地图完成后，以同硬件、可比发布配置、相同输入、功能、画质、物理精度及控制行为比较 Godot/Bevy。预热 30 秒、采样 120 秒，交替执行各五次；记录帧时间 P50/P95/P99、物理与推理耗时、仿真时间/墙钟时间、CPU、RSS/峰值及失败次数。录像与高频证据记录另行运行，采样结果注明场景范围。

开发效率从实际任务记录调研、修改、构建、启动、定位及回归耗时，覆盖控制接入、接触修复、资产导入和材质迭代。

分别核验 Apple Silicon macOS/Metal、DGX Spark Linux ARM64/Vulkan、Windows 实际架构与 MSVC/图形后端。依赖支持、先行案例、项目构建和项目运行单独记录。
