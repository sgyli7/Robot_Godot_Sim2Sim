# Frozen head_roll source-limit row probe (diagnostic only)

Date: 2026-09-28. This is a one-step, robot-only experiment for the leg and roller MicroDuck models. It adds no production limit-law selection, source contact qualification, or BAM external-load availability.

## Boundary and implementation

The `sim2sim_source_limit_probe` Cargo feature and `paired_force_probe --head-roll-source-limit-diagnostic` must **both** be selected. The probe accepts only two SHA-bound scratch definitions with the frozen leg/roller source-limit parameters and native collision hulls. Their SHA256 values are `e91d67ba25efe3b61b65e77c754a4278f24f37253a86acdf81543a7de51f67bb` and `6f88aa286e487c031250b427595a640b9f597604c9a20dcbca6fd69c49109c40`. The files are `.scratch/source_limit_probe_v1/{leg,roller}_enriched_with_hulls.json`; they merge only `mesh_graphadr` and `mesh_graph` from the previously verified native-hull definitions into the source-limit-enriched definitions. The merge checked all common model fields and source identity before writing those scratch files. The formal frozen definitions and assembly defaults remain unchanged. The CLI refuses any time step other than one native `1/60 s` solver step.

For the one `head_roll` AngX row, the new diagnostic branch computes source impedance from compiled `jnt_solimp`, reference acceleration from `jnt_solref` with `refsafe` (`τ=max(solref[0],2·dt)`), and regularization `R=(1−d)/d·dof_invweight0[head_roll]`. Its only supported source interpolation is the frozen `midpoint=0.5, power=2` quadratic curve; the setter rejects other curves. At a strictly positive upper violation, the source Jacobian is `J=−e_head_roll`, whereas the native row uses `+e_head_roll` and a positive impulse that decreases joint velocity. Therefore the native row uses `cfm_gain=R` and `rhs=dt·aref−qdot_pre`; a lower violation uses the reflected sign. The regularizer uses the **compilation-time** inverse weight, not the pose-dependent `J M⁻¹ Jᵀ`. At/below the margin the row has zero impulse bounds. Its `rhs_without_bias` is deliberately identical to `rhs`, so Rapier's later unbiased stage cannot cancel the physical soft-limit impulse after position integration. This experiment does not inject MuJoCo's solved constraint force as an oracle.

## Paired result

The tracked source generator `crates/dev_tools/python/scripts/limit_law_matrix.py` produced SHA-bound source matrices `c30cfd248770f4eb761672616f6417ead877337624f590f8602459475b730a9e` (leg) and `48b23a63c220f9713f38a022a9254d920aad67fd2411ca87119f83fd970f027d` (roller). The tracked `crates/dev_tools/python/scripts/source_limit_probe_matrix.py` generates the same seven depths × three initial velocities for each model, and launches a new direct Rapier world per case, with zero actuator torque and no scene contacts. Raw native reports, input qpos/qvel hashes, and per-case error values are recorded in `.scratch/source_limit_probe_v1/matrix_result.json` (SHA256 `4668e6c8affd2df87a974f65b902d4b8c85ecd690219f9e35561a7c4dc239bd1`). “Active” below means a physically enabled unilateral impulse bound; Rapier still reserves a no-op row with `[0,0]` bounds at inactive states, whereas MuJoCo does not allocate that row. The earlier aggregate SHA `e8cb2b1d96219b94baa88c097716c0aaba4d16c1e3996f4a3367cc3505b6af09` was generated before four input-provenance hashes were added to `frozen_inputs`; removing only those four keys from the current JSON reproduces that old SHA exactly. All 42 raw native reports are byte-identical across the two most recent runs.

## Default-path isolation

With the source-limit feature compiled but **without** its CLI switch, six leg/roller cases (inside, shallow upper violation, deeper upper violation) produced byte-identical JSON to a build without the feature, while retaining the old native hard limit. SHA-bound reports and build variants are in `.scratch/source_limit_probe_v1/no_optin_parity.json` (SHA256 `3551622a2886d8f1bd5eab8f331dedbab6fe54807423f15b9ff257cd2c061059`). A build without the feature explicitly refuses the CLI switch and writes no output. `cargo check` passed both the feature-on probe and the existing observation-only build; `cargo fmt --all -- --check` passed.

These 42 single-row cases do **not** establish multi-step stability, simultaneous limits/contact coupling, source contact behavior, or BAM `previous_solve_load`. The scratch definitions are not production inputs, and the diagnostic selector must remain default-off until those gates are separately examined.
