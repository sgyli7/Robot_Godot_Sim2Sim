# 源端 60/60 PPO 探索流程

本页约束隔离的源端训练烟测。源端使用 MuJoCo Warp 与 BAM，物理和策略均为 60 Hz；探索产出不自动成为生产 candidate。完整依赖闭包、可信的一次性许可和正式候选审查仍是生产学习入口的前置条件，见[实施交接](handoff.md)。

## 最小生命周期

1. 固定 upstream commit、科学依赖版本、BAM 配置、种子与实际环境配置，保存全部输入 SHA256。保持 61 维观察与 14 维动作合同。
2. 训练进程使用训练所需的自动重置；记录采样数量、PPO 更新数量、优化器状态和异常边界。仅创建环境或输出 checkpoint 不能证明实际执行了更新。
3. 保存显式 checkpoint 及其身份，在独立新进程中以同一源任务、60/60 和 BAM 复载，核对优化器与策略状态。
4. 评估关闭自动重置，使用确定性推理，连续记录自然首回合全部观察、动作和真实物理步骤。保留终止原因与完整轨迹，不能拼接重置后的片段冒充持续站立。
5. 将训练成功、复载成功与行为门槛分别报告。一次 PPO 更新与 checkpoint 复载成功，只证明执行链可运行，不证明 Idle、九技能或 Rapier Sim2Sim 合格。

历史探索已证明该最小链路可执行，但没有取得合格 Idle；长期训练与多种子评估须独立进行，见[源端评估流程](source_rl_multirun_60hz.md)。源端稳定也不能代替目标 Rapier 的接触、执行器和 BAM 外载验收。

## 产出归档

脚本、实际配置、收据、日志、checkpoint、ONNX、逐帧数据和失败 traceback 保存到所属仓库的历史备份目录 `/home/ethan/ProjectBackups/<date>/Sai_Lab/<run_name>/`，保留索引及文件 SHA256，不入库。实验开始前明确学习预算和授权；探索结果不得写成生产学习准入或自动晋升 candidate。
